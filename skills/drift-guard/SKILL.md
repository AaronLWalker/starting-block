# Drift guard

Drift happens when the same fact lives in two places and people update one. The fix is to give each
fact one home and make everything else either generated from it or checked against it.

## 1. Map the facts

List where the fact appears (code, config, docs, generated output) and pick the **source of truth**:

- Prefer what's already authoritative at runtime (the compose file, the routes table, the schema).
- Facts that live nowhere else (descriptions, groupings, display names) go in a small **manifest**,
  e.g. `docs/services.yaml`, that people edit.
- Everything a reader sees is then **generated** (from the source and the manifest) or **checked**
  (where it can't be generated, like a hand-written config that must agree).

Say what goes where before writing code, and check it with the user if it changes how they edit things.

## 2. Write `build` and `check`

One script, in the repo's main language, with two commands:

- **`build`** writes the generated files. It's deterministic: same inputs, byte-identical output, so
  the check can compare.
- **`check`** exits non-zero on any disagreement:
  - the generated file differs from what `build` would write;
  - something in the source has no manifest entry, or the manifest lists something that's gone;
  - cross-checked facts disagree (a port, a path, an image name, a redirect);
  - optionally, live checks (links answer, the service responds), skipped under **`--offline`**.

Each failure message names the thing, both values, and the fix: `services.yaml lists 'bazarr' but
docker-compose.yml has no such service; remove it or add the service`. End with the command to run.

Put a "generated by `<script>`; edit `<manifest>`" comment at the top of the generated file if its format
allows comments.

## 3. Hook it in

Use what the repo already has: `pre-commit`, husky, lefthook, a Makefile target. Without any of them,
a tracked hook directory:

```sh
#!/bin/sh
# .githooks/pre-commit: keep <output> in step with <sources>.
# Enable once per clone:  git config core.hooksPath .githooks
if git diff --cached --name-only | grep -qE '^(path/to/source\.yml|docs/manifest\.yaml|docs/output\.html)$'; then
    if ! python3 scripts/<name>.py check --offline; then
        echo
        echo "Update docs/manifest.yaml, then run: python3 scripts/<name>.py build"
        echo "(To commit anyway: git commit --no-verify)"
        exit 1
    fi
fi
```

- Run only when relevant paths are staged, offline, in well under a second.
- Make it executable (`chmod +x`) and commit it.
- Add the full `check` to CI if the repo has CI, so a skipped hook still gets caught.

## 4. Document it

In the repo's instructions file (`CLAUDE.md`, `README.md`, `CONTRIBUTING.md`):

- **`<manifest>` is the source of truth** for `<output>`; `<output>` is generated, don't edit it by hand.
- "When you add, remove or change a `<thing>`": the numbered steps (edit manifest, build, check).
- How to enable the hook in a new clone.

## 5. Prove it

1. `build`, then `check`: passes.
2. Introduce each kind of drift by hand (edit the output, add a source entry, change a cross-checked value):
   `check` fails with a message that says what to do.
3. Stage the drifted file and commit: the hook blocks it.
4. Restore, `build`, `check`, commit.

The backlog index this plugin keeps is the same pattern: `backlog.py check` fails when `issues/README.md`
disagrees with the issue files, and `backlog.py index` regenerates it.
