# Drift guard

Drift happens when the same fact lives in two places and people update only one. The fix: give each
fact one home, and make everything else either generated from it or checked against it.

## 1. Map the facts

List where the fact appears (code, config, docs, generated output). Pick the **source of truth**:

- Prefer what's already authoritative at runtime: the route table, the schema, the config file.
- Facts that live nowhere else (descriptions, groupings, display names) go in a small **manifest** that
  people edit, e.g. `docs/endpoints.yaml`.
- Everything else is **generated** from those, or **checked** against them where it can't be generated
  (a hand-written config that must agree).

Say what goes where before writing code. Check with the user if it changes how they edit things.

## 2. Write `build` and `check`

One script, in the repo's main language:

- **`build`** writes the generated files. Same inputs, byte-identical output.
- **`check`** fails on any disagreement: the generated file differs from what `build` would write; the
  source has something the manifest lacks, or the reverse; cross-checked values disagree. Optional live
  checks (links answer) are skipped under `--offline`.

Each failure names the thing, both values, and the fix, e.g. `endpoints.yaml lists GET /v1/users but the
router has no such route; remove it or add the route`, and ends with the command to run. Mark the
generated file "generated by `<script>`; edit `<manifest>`" if its format allows comments.

## 3. Hook it in

Use what the repo already has (pre-commit, husky, lefthook, a Makefile target, CI). Otherwise add a
tracked hook. Git runs hooks with its own `sh`, Git Bash's on Windows, so this works on every platform:

```sh
#!/bin/sh
# .githooks/pre-commit: keep <output> in step with <sources>.
# Enable once per clone:  git config core.hooksPath .githooks
for PY in python3 python "py -3"; do $PY -c "" >/dev/null 2>&1 && break; done  # Windows: skip the Store stub
if git diff --cached --name-only | grep -qE '^(src/routes\.py|docs/endpoints\.yaml|docs/api\.md)$'; then
    if ! $PY scripts/check_docs.py check --offline; then
        echo
        echo "Update docs/endpoints.yaml, then run: python scripts/check_docs.py build"
        echo "(To commit anyway: git commit --no-verify)"
        exit 1
    fi
fi
```

- Run only when relevant paths are staged, offline, and fast.
- Commit the hook as executable: `git add --chmod=+x .githooks/pre-commit` (plain `chmod` doesn't reach
  git on Windows).
- Add the full `check` to CI too, so a skipped hook still gets caught.

## 4. Document and prove it

In the repo's instructions file, say which file is the source of truth, that the output is generated,
the steps for adding or changing an entry, and how to enable the hook in a new clone.

Then prove it: `build` and `check` pass. Introduce each kind of drift by hand and see `check` fail with a
useful message. Stage a drifted file and see the hook block the commit. Restore, `build`, `check`, commit.
